# 素材上传与发布教程

这份教程用于独立维护个人网站内容。日常更新时，你只需要做三件事：

1. 把素材文件放进对应文件夹。
2. 编辑 `content/site-content.js`。
3. 运行 `scripts/publish.ps1` 发布到 GitHub Pages。

网站地址：

```text
https://wuxuefan1207-art.github.io/
```

## 一、推荐工具

推荐使用 Visual Studio Code 编辑网站文件。

打开方式：

1. 打开 VS Code。
2. 选择 `File` -> `Open Folder`。
3. 打开这个文件夹：

```text
C:\Users\吴雪凡\Documents\Personal website
```

之后主要编辑这个文件：

```text
content/site-content.js
```

## 二、文件夹分工

```text
assets/
  photos/        摄影作品图片
  thumbnails/    视频封面图
  videos/        小体积本地视频
content/
  site-content.js  网站内容表
scripts/
  publish.ps1      一键发布脚本
```

不要直接修改 `.git/` 文件夹。

## 三、素材命名规则

建议所有素材文件名使用英文、数字和短横线，不使用空格。

推荐格式：

```text
日期-主题-序号.扩展名
```

示例：

```text
260307-yulan-01.jpg
260521-hangzhou-street-01.jpg
260521-city-walk-cover.jpg
260521-city-walk.mp4
```

如果相机导出的文件是 `.JPG`，也可以继续使用，但内容表里的路径必须和真实文件名完全一致。

## 四、添加摄影作品

### 1. 放入图片

把照片复制到：

```text
assets/photos/
```

例如：

```text
assets/photos/260307-yulan-01.JPG
```

### 2. 编辑内容表

打开：

```text
content/site-content.js
```

找到：

```js
photos: [
```

在它下面添加一段：

```js
{
  title: "玉兰",
  date: "2026-03-07",
  category: "日常",
  location: "杭州",
  description: "如玉质感。",
  src: "assets/photos/260307-yulan-01.JPG",
},
```

字段说明：

- `title`：照片标题
- `date`：日期，必须使用 `YYYY-MM-DD`
- `category`：分类，页面会自动生成筛选按钮
- `location`：拍摄地点
- `description`：点击照片后弹窗里的说明
- `src`：图片文件路径

### 3. 图片大小建议

GitHub Pages 可以放图片，但不适合放大量原始大图。建议：

- 单张展示图尽量控制在 1-3 MB。
- 宽边 2000-3000 px 通常已经足够网页展示。
- 原始大图可以另外备份，不一定放进网站仓库。

## 五、添加文字

文字区目前是文章入口。你可以先放标题和摘要，完整文章以后再补页面。

打开：

```text
content/site-content.js
```

找到：

```js
writing: [
```

添加：

```js
{
  title: "一次拍摄之后的记录",
  date: "2026-05-21",
  category: "札记",
  excerpt: "这是一段关于拍摄现场、剪辑想法和当时状态的记录。",
  url: "#",
},
```

字段说明：

- `title`：文章标题
- `date`：发布日期
- `category`：分类
- `excerpt`：摘要
- `url`：文章链接

如果还没有完整文章，`url` 可以先写：

```js
url: "#",
```

如果以后有完整文章页面，例如：

```text
posts/photo-notes.html
```

就改成：

```js
url: "posts/photo-notes.html",
```

## 六、添加视频

视频有两种维护方式。

### 方式 A：推荐使用外部视频链接

适合 Bilibili、YouTube、Vimeo。

先把视频封面图放进：

```text
assets/thumbnails/
```

例如：

```text
assets/thumbnails/260521-city-walk-cover.jpg
```

然后在 `content/site-content.js` 的 `videos` 数组里添加：

```js
{
  title: "城市一分钟",
  date: "2026-05-21",
  description: "一次关于街道、声音和傍晚光线的剪辑练习。",
  url: "https://www.bilibili.com/video/BVxxxxxxxxxx",
  thumb: "assets/thumbnails/260521-city-walk-cover.jpg",
},
```

这种方式最适合长期维护，因为 GitHub Pages 不需要承载大视频流量。

### 方式 B：上传小体积本地视频

适合很短的视频。

把视频文件放进：

```text
assets/videos/
```

例如：

```text
assets/videos/260521-city-walk.mp4
```

再添加：

```js
{
  title: "城市一分钟",
  date: "2026-05-21",
  description: "一段短视频。",
  url: "assets/videos/260521-city-walk.mp4",
  thumb: "assets/thumbnails/260521-city-walk-cover.jpg",
},
```

建议本地视频尽量小，最好不要把大视频直接放在 GitHub 仓库里。

## 七、编辑时最容易出错的地方

`site-content.js` 是 JavaScript 数据文件，格式要保持严格。

注意：

- 文本要放在英文双引号里：`"文字"`
- 每个字段后面要有英文逗号：`,`
- 每个条目用 `{ ... }` 包起来
- 条目之间要用英文逗号分隔
- 路径里的斜杠使用 `/`，不要写成 `\`

正确：

```js
src: "assets/photos/260307-yulan-01.JPG",
```

错误：

```js
src: "assets\photos\260307-yulan-01.JPG"
```

## 八、发布网站

每次改完内容后，打开 PowerShell，进入网站目录：

```powershell
cd "C:\Users\吴雪凡\Documents\Personal website"
```

然后运行：

```powershell
.\scripts\publish.ps1 -Message "Update website content"
```

如果 PowerShell 提示脚本执行策略限制，可以改用：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\publish.ps1 -Message "Update website content"
```

脚本会自动完成：

1. 检查 `content/site-content.js` 语法。
2. 查看 Git 修改。
3. `git add .`
4. `git commit`
5. `git push`

如果只是想预演检查，不想真的提交，可以运行：

```powershell
.\scripts\publish.ps1 -DryRun
```

推送完成后，等待 1-3 分钟，刷新网站：

```text
https://wuxuefan1207-art.github.io/
```

## 九、发布前检查清单

发布前快速看一遍：

- 图片或视频封面已经放进正确文件夹。
- `src`、`thumb`、`url` 路径和文件名完全一致。
- 日期格式是 `YYYY-MM-DD`。
- 每个新增条目末尾有英文逗号。
- 本地双击 `index.html` 能正常打开。
- 运行发布脚本没有红色报错。

## 十、常见问题

### 页面没有更新

GitHub Pages 可能有延迟。等待 1-3 分钟后强制刷新浏览器。

Windows 常用强制刷新：

```text
Ctrl + F5
```

### 图片不显示

优先检查三件事：

1. 图片是否真的在 `assets/photos/`。
2. `src` 路径是否写对。
3. 文件扩展名大小写是否一致，比如 `.JPG` 和 `.jpg`。

### 运行发布脚本失败

先确认 Git 路径存在：

```text
D:\Tool\Git\cmd\git.exe
```

如果 Git 安装到别的位置，需要修改：

```text
scripts/publish.ps1
```

里面的 Git 路径。

### 不想公开真实邮箱

当前仓库已经配置了 GitHub no-reply 邮箱，提交时不会公开你的 Google 邮箱。
